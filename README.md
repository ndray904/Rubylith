# Rubylith

A background remover that runs entirely in the browser. Open a photo and it cuts out the subject.
You can then refine the edge, touch it up with brushes, and save it as PNG, WebP, JPG, PDF or SVG.
Nothing is uploaded: the AI models run on the device.

**Use it here: https://ndray904.github.io/Rubylith/**

## Features

- **Two AI models**
  - **BiRefNet-lite:** best quality; needs a GPU through WebGPU, so Chrome or Edge on a computer.
  - **ISNet:** fast, and works everywhere, including phones.
  - **Auto** picks the right one for the device. If BiRefNet's GPU result is broken, the app falls back to ISNet.
- **Graphic / logo mode** removes a flat or checkerboard background by color, which keeps text and thin lines.
  Painted artwork is detected and sent to the AI model instead.
- **Edge refinement**
  - edge-aware matting (a color-guided filter in a band around the edge)
  - smooth, feather, contrast and shift-edge controls
  - stray-bit removal and color decontamination
- **Touch-up tools**
  - Restore and Erase brushes, with logarithmic size and adjustable hardness
  - **Area removal / Area restore:** tap a region and every connected pixel of similar color is removed or brought back
  - undo and redo
  - pinch-zoom that doesn't leave stray marks
- **Convenience**
  - auto-save of the last session
  - models are saved in the browser after the first download

## Layout

| Path | What it is |
|---|---|
| `docs/rubylith.html` | The app: one HTML file with inline CSS and JS. This is the page published to claude.ai. |
| `docs/index.html` | The same page wrapped in a full HTML document. GitHub Pages serves it from `docs/`. It's generated by `tools/build_index.py`. |
| `docs/m/bir6/` | BiRefNet-lite, repaired for WebGPU. Stored as base64 `.txt` chunks because the artifact host serves only standard web file types. |
| `docs/m/small/` | ISNet (quantized), as base64 chunks. |
| `docs/ort/jsep/` | The ONNX Runtime Web 1.22.0 WebAssembly binary (JSEP build), as base64 chunks. Its JavaScript loads from jsDelivr. |
| `tools/model/` | The scripts used to make BiRefNet run correctly on WebGPU (see below). |
| `licenses/` | Third-party license texts. |

## Running it locally

```sh
python3 tools/build_index.py     # after editing docs/rubylith.html
python3 -m http.server 8000 -d docs
```

Then open http://localhost:8000. WebGPU, which BiRefNet needs, only works on `localhost` or over HTTPS.

## How BiRefNet was made to work on WebGPU

The starting point was the BiRefNet-lite ONNX export (fp32, about 224 MB). It was changed in four ways:

1. **Weights stored at half size.** Weights are stored as fp16 and converted back to fp32 by `Cast` nodes, which halves the download.
   Large layers are split into trees of at most 6 inputs (`fanout.py`), because a WebGPU kernel gets only 8 storage buffers.
2. **Fixed layout steps pre-computed.** `simp.py` runs onnx-simplifier at the fixed 1×3×1024×1024 input size.
   This cuts the graph from 17,636 nodes to 4,345 and removes every ScatterND, Where, Equal and Shape step.
   It then re-stores the weights as fp16.
3. **Clean-ups after simplifying.**
   - `concat_tree.py` re-splits the Concat nodes the simplifier merged.
   - `const16.py` stores the large constants as fp16. They are integer-valued, so fp16 holds them exactly.
4. **Broken GPU step replaced.** `gathernd.py` replaces all 80 GatherND nodes with an equivalent flat `Gather`.
   In ONNX Runtime Web 1.22, the WebGPU GatherND shader fails to compile (`no matching constructor for 'i32(vec4<u32>)'`).
   The node then silently does nothing, so BiRefNet returned garbage on every GPU.

The `.onnx` files themselves are not in the repo: they are 120–224 MB, over GitHub's file limit.
The app's model is exactly the base64 chunks joined together and decoded.
`tools/model/run_cpu.py` runs a model with ONNX Runtime on the CPU to check its output:

```sh
python3 tools/model/run_cpu.py photo.jpg model.onnx mask.png
```

**Limitations**

- BiRefNet needs about 4.4 GB while it runs. That is over WebAssembly's 4 GB limit, so it only works on a GPU.
- The fast model looks at the photo at 1024 px, so very thin strands such as whiskers can be lost.
